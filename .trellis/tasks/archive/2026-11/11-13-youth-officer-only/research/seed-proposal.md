# Proposal only: persistent synthetic officer demonstrations

The existing frontend synthetic mock is sufficient for this cleanup. It creates no database rows; decisions reset on reload. README documents this currently available method only.

The retained stage-two seed CLI requires an already identity-verified draft and does not submit it. Scenario fixtures create temporary DB/storage and clean them afterward. P6 live reset and the historical blocked-review helper must not be repurposed as a normal persistent seed method.

If persisted synthetic applications are requested later, the minimum separate proposal is a guarded development CLI that reuses synthetic youth scenario inputs and public create/consent/subsidy/upload/submit handlers. It must refuse non-demo databases, preserve identity/submission blockers, mark owned rows/files and clean only that ownership set. Never manufacture a successful review or change engine decisions.

No seed CLI, endpoint, migration or new seed test is implemented in this task. Its implementation requires a separate scope/approval decision.
